# 業務データ処理の小型技術サンプル 5件

採用担当・技術レビュー担当向けの**公開用再実装草案**です。全データは架空です。既存社内コード、実帳票、顧客・銀行・メール情報は使用していません。外部API、認証情報、ネットワーク接続、追加パッケージは不要です。GitHubへの公開・pushは実施していません。

## 実務との区別・AI支援

本人提供の作業記録にある月ずれ修正、帳票差額整理、重複防止、AI読取結果の人手確認、計算方式の照合を説明するため、架空データで新規作成したサンプルです。実務コードの転載や、実務と同一の実装であることの証明ではありません。

この成果物は依頼された課題から新規に構成したサンプルで、本人の過去の実務コード、納品物、実運用システムではありません。本人が実務で担当した範囲や成果を証明する資料ではなく、数値成果、実運用経験、本人単独実装を主張しません。設計・コード・テスト・本READMEの作成にはCodexのAI支援を使用しています。本人による内容確認・説明可能性の確認は公開前に必要です。

## 起動

Python 3.12以降。ダウンロードしたフォルダに移動して実行します。OS依存の追加設定はありません。

```console
python demos.py all
python demos.py monthly
python demos.py reconcile
python demos.py idempotency --db demo.sqlite3
python demos.py idempotency --db demo.sqlite3
python demos.py ocr
python demos.py rounding
python -m unittest -v
python verify.py
```

`python verify.py`はテストと5デモを実行し、`evidence/`内の証拠を上書き再生成します。同梱の検証結果を残したい場合は、実行前にコピーしてください。同梱証拠のソースハッシュは検証実行時点のもので、その後のREADMEのみの文書補足は含みません。

2回目の同じDBへの実行では既存IDを返し、作成件数は増えません。DBを指定しなければメモリ内で完結し、終了時に消えます。ファイルDBはローカルに生成されるため、公開対象には含めません。

## 仕様と設計理由

| デモ | 入力と結果 | 設計理由 |
|---|---|---|
| 月集計 | 転記時に保存済みの`basis_month`で集計。9月基準の2件は10月に転記されても合計2,000 | 実行日や転記日から基準月を再推定せず、再実行で対象月がずれる問題を避ける |
| 請求照合 | IDで1対1照合し、区分差・日付差・欠損・金額差・不正日付を分類 | 差異を複数保持し、最初の差だけで他の問題を隠さない。重複IDは曖昧なので拒否 |
| 重複作成防止 | 同じ要求キーと同じ内容は同じID。同じキーで内容が異なればエラー | SQLiteの一意制約とトランザクションで二重クリックと再起動後の再試行を扱う。作成と要求台帳が同じDB内で確定 |
| OCR訂正・承認 | 架空OCRの`I200`を人間役が1,200に訂正し、版を指定して承認 | 元値・訂正値・担当者役・版を残す。古い版の承認を拒否し、承認後の訂正で承認を無効化 |
| 端数比較 | 架空105×3、率10%で、切捨ては明細単位30・請求書単位31。四捨五入では差の方向も変わる | 率は10進文字列またはDecimalのみ受け付け、float・整数・boolを拒否します。Decimalと整数の最小通貨単位を用い、丸め位置の影響を明示 |

端数デモは**税務助言ではありません**。単一率・非負整数の架空計算であり、適法な方式の選択、実際の税額や申告処理を案内するものではありません。

## 構成

面談での説明ポイントは、保存済み基準月を使う理由（保存処理自体は範囲外）、差額を分類して自動修正せず残すこと、同一要求キーの再送と内容不一致の扱い（外部送信までは保証しない）、訂正後の版指定承認（実OCRではない）、丸め位置とfloat拒否（税務上の正解を決めない）です。

- `demos.py`: 5つの独立した関数・クラスとCLI入口
- `fixtures.json`: 人物・取引先名を持たない架空入力
- `test_demos.py`: 正常、異常、再試行、同時実行の検証
- `evidence/`: 実際に実行したテスト結果、CLI出力、検証要約
- `.gitignore`: ローカルDB・Pythonキャッシュの公開混入防止

## 検証方針

正常系は期待金額・分類・承認状態を比較します。異常系は不正月、重複ID、不正日付、内容の異なるキー再利用、OCRの不正金額・古い版、負値等を検証します。再試行系は月集計・照合の再現性、DB再オープン、確定前例外からの復旧、承認の再送を検証します。4ワーカー・8要求の同時クリックでは作成1件を検証します。実行済みの証拠は`evidence/`を参照してください。

## 制限と実運用で必要なこと

月集計は転記済みの入力を受けるため、基準月の入力画面・永続保存・締め処理は実装していません。請求照合は厳密ID一致のみで、曖昧一致や差異の自動修正はしません。金額は非負整数だけを扱い、返金・複数通貨は対象外です。

重複防止は単一SQLite DB内に限ります。別DBや外部サービスの副作用には対応せず、分散環境のexactly-once保証を主張しません。キーの採番・保管期間・認証は実運用側の設計課題です。OCRは実OCRエンジンを呼ばず、担当者は文字列の役名です。公開プロパティは読み取り専用で、fields/eventsは深いコピーを返します。値の変更はcorrectを通して版更新と承認無効化を行います。Python内部属性への直接操作に対する改ざん完全保証はしません。監査ログはメモリ上の説明用で、改ざん防止、権限制御、時刻証明、永続化はありません。訂正要求自体の重複排除はなく、承認の同版再送のみを抑制します。
